# แผนเปลี่ยนทิศ · PARALLAX เป็น CRM แบบ Salesforce

เขียน 2026-10-11 · แทนที่ `simplify-plan.md` (แผนนั้นปรับคอนโซลเดิม แผนนี้เปลี่ยนตัวผลิตภัณฑ์)

> แผนก่อนหน้าผมแนะนำว่า *ไม่ทำ pipeline / deal* — เจ้าของตัดสินใจแล้วว่าจะไปทางนี้
> แผนนี้จึงทำตามทิศนั้นเต็มตัว ข้อกังวลที่เหลืออยู่ในหัวข้อความเสี่ยง ไม่ได้ซ่อนไว้

---

## ทิศใหม่ในประโยคเดียว

**CRM ภาษาไทยสำหรับ SME ที่โครงแบบ Salesforce ใช้ง่ายกว่า และทำสิ่งที่ Salesforce ทำไม่ได้:
บอกได้ว่าการติดตามลูกค้าทำให้ขายได้เพิ่มจริงเท่าไร**

Salesforce บอกว่าขายได้เท่าไร — PARALLAX บอกว่า*การกระทำของคุณ*ทำให้ขายได้เพิ่มเท่าไร
เครื่องวัดผลแบบกันกลุ่มไว้ (holdout) ที่สร้างไว้แล้วคือจุดต่าง ไม่ใช่ของที่ต้องทิ้ง

---

## เทียบกับ Salesforce · มีอะไรแล้ว ต้องสร้างอะไร

| Salesforce | PARALLAX วันนี้ | ต้องทำ |
|---|---|---|
| **Contact** | `customers` + `customer_features` 31 ฟิลด์ต่อคน | มีข้อมูล ไม่มีหน้า · **ไม่มีอีเมล/เบอร์** (เก็บแค่ hash) |
| **Account** (บริษัท) | ไม่มี | สร้างใหม่ |
| **Lead** | ไม่มี — Reach หากลุ่มคล้ายได้ แต่ไม่เป็นเรคคอร์ด | สร้างใหม่ · รวมเป็นขั้นของ contact |
| **Opportunity** (ดีล) | ไม่มี | **สร้างใหม่ — หัวใจของ pipeline** |
| **Activity / Task** | `events` (ระบบบันทึก) + `messages` | สร้างใหม่: โทร · นัด · โน้ต · LINE · งาน |
| **Campaign** | `campaigns` + กลุ่มที่กันไว้ + `attributions` | **มีแล้ว และวัดผลได้ดีกว่า Salesforce** |
| **Einstein** (AI) | ความเสี่ยงหาย · วันซื้อครั้งถัดไป · วิธีที่แนะนำ | **มีแล้ว** → ย้ายไปเป็นแผงข้างเรคคอร์ด |
| **Reports / Dashboard** | หน้าผลที่วัดได้ · ROI | ปรับเป็นรายงาน pipeline + แคมเปญ |
| **ค้นหาทั้งระบบ** | **ไม่มีเลยสักช่อง** | สร้างใหม่ (⌘K) |
| **List view + ตัวกรอง** | ไม่มี | สร้างใหม่ |
| **Kanban** | ไม่มี | สร้างใหม่ |
| **เจ้าของเรคคอร์ด** | สิทธิ์ระดับบัญชีเท่านั้น (`tenant_users`) | เพิ่ม `owner_id` |

**สรุป** — ส่วนที่ยากที่สุดของ CRM (ฐานข้อมูลหลายบัญชี · RLS · login · นำเข้าข้อมูล · AI · วัดผล)
**มีแล้ว** ส่วนที่ขาดคือส่วนที่ผู้ใช้เห็น: เรคคอร์ด · ดีล · กิจกรรม · ค้นหา

## ห้าเรื่องที่ต้องตัดสินใจก่อนเขียนโค้ด

### D1 · เก็บอีเมลและเบอร์โทรจริง ← เรื่องนี้ไม่ใช่ทางเลือกแล้ว

ตอนนี้ `identities` เก็บ **sha256 อย่างเดียว** CRM ฝั่งขายที่โทรหาใครไม่ได้ไม่ใช่ CRM
ทิศใหม่จึงบังคับให้เก็บค่าจริง — แต่ต้องเก็บแบบนี้:

- เข้ารหัสในฐานข้อมูล (Supabase Vault / pgcrypto) · เก็บ hash ไว้ใช้จับคู่ต่อ
- สิทธิ์ระดับฟิลด์ — ไม่ใช่ทุกคนในทีมต้องเห็นเบอร์
- PDPA: บันทึกวัตถุประสงค์ · ระยะเวลาเก็บ · ส่งออก/ลบตามคำขอ · แจ้งเหตุรั่ว 72 ชม.
- บันทึกว่าใครเปิดดูข้อมูลติดต่อเมื่อไร

### D2 · ขายให้บริษัท (B2B) หรือคนทั่วไป (B2C)

Salesforce ออกแบบมาเพื่อ B2B (บริษัท → ผู้ติดต่อ) แต่ SME ไทยจำนวนมากขายคนทั่วไป
**แนะนำ: บริษัทเป็นช่องที่ไม่บังคับ** — ผู้ติดต่อที่ไม่มีบริษัทคือ "ลูกค้าบุคคล"
(แบบ Person Account ของ Salesforce) โครงเดียวใช้ได้ทั้งสองแบบ

### D3 · โมเดลราคา

ตอนนี้คิดตามจำนวนลูกค้าที่ระบุตัวได้ และเขียนบนหน้าราคาว่า *"Not on seats"*
CRM ที่ทีมขายหลายคนใช้ คิดต่อผู้ใช้สมเหตุสมผลกว่า
**ทางเลือก** — ต่อผู้ใช้ · ตามฐานลูกค้า (แบบเดิม) · ผสม (ผู้ใช้ราคาต่ำ + ขั้นตามฐานลูกค้า)

### D4 · เครื่องวัดผล — เก็บเป็นจุดต่าง (แนะนำ)

ถ้าไม่มีมัน PARALLAX คือ HubSpot ที่ด้อยกว่าและไม่มีแผนฟรี
ถ้ามี มันคือ CRM ตัวเดียวในตลาดไทยที่พิสูจน์ได้ว่าการติดตามทำให้เกิดยอดจริง

### D5 · บัญชีเดโมพรรคการเมือง

ข้อจำกัดเดิมคือบัญชีนี้ทำได้แค่ **บริหารสมาชิกภาพ ห้ามโน้มน้าวผู้มีสิทธิ์เลือกตั้งหรือยิงเป้ารายบุคคล**
pipeline · ลีด · ดีล บนบัญชีพรรค คือเครื่องมือหาเสียงรายบุคคลพอดี
**แนะนำ: ถอดออกจากเดโม CRM** แทนด้วยบัญชีตัวอย่าง B2B สมมุติ (เช่น ตัวแทนจำหน่ายวัสดุ · เอเจนซี)

## โครงข้อมูลใหม่

```
accounts         บริษัท        id · ชื่อ · อุตสาหกรรม · ขนาด · เว็บไซต์ · owner_id
contacts         ผู้ติดต่อ      = customers เดิม + account_id? · อีเมล* · เบอร์* · LINE* · ตำแหน่ง
                                 · stage (ลีด → สนใจ → ลูกค้า → เสีย) · แหล่งที่มา · owner_id · แท็ก
pipelines        ท่อขาย       ตั้งได้ต่อบัญชี
pipeline_stages  ขั้น          ค่าตั้งต้น: ติดต่อแล้ว → นัดคุย → เสนอราคา → ต่อรอง → ได้ / ไม่ได้
deals            ดีล           ชื่อ · มูลค่า · ขั้น · โอกาส% · วันคาดว่าจะปิด · owner_id · เหตุผลที่เสีย
activities       กิจกรรม       ประเภท (โทร·นัด·โน้ต·อีเมล·LINE·งาน) · เรื่อง · รายละเอียด
                                 · กำหนด · เสร็จเมื่อ · ผูกกับ contact/account/deal
                                                                    * = เข้ารหัส (D1)
```

**เก็บไว้ทั้งหมด:** `transactions` · `line_items` · `campaigns` · `attributions` · `customer_features`
— ประวัติการซื้อกลายเป็นส่วนหนึ่งของไทม์ไลน์ลูกค้า

RLS ทุกตารางใหม่ผูก `tenant_id` เหมือนเดิม (39 นโยบาย → ราว 55) · ด่าน schema-parity ครอบตารางใหม่อัตโนมัติ

## หน้าจอ · โครง Salesforce คลิกน้อยกว่า

### เมนู 6 รายการ (เดิม 9)

```
หน้าแรก · ลูกค้า · บริษัท · ดีล · งาน · แคมเปญ          [⌘K ค้นหา]  [+ สร้าง]  [ฉัน ▾]
```

ตั้งค่า · ค่าใช้จ่าย · นำเข้าข้อมูล อยู่ใต้เมนู "ฉัน" — ไม่ใช่เมนูหลัก

### หน้าเรคคอร์ด — ลายเซ็นของ Salesforce

```
┌──────────────────────────────────────────────────────────────────────────┐
│ สมชาย ใจดี · บ.ไทยวัสดุ · ผู้จัดการจัดซื้อ             [โทร] [LINE] [+ ดีล] │
│ มูลค่ารวม ฿482,000 · เจ้าของ: คุณแนน · ติดต่อล่าสุด 3 วันก่อน               │
├──────────────────────────────────────────────────────────────────────────┤
│  ลีด ──── สนใจ ──── [ ลูกค้า ] ──── เสีย                                  │
├──────────────────────────────────────────┬───────────────────────────────┤
│ ┌ บันทึกการโทร · นัด · โน้ต … ──────────┐ │ ข้อมูลเชิงลึก                  │
│ └──────────────────────────────────────┘ │ ⚠ กำลังจะเงียบ — เลยรอบไป 26 วัน│
│                                          │ คาดว่าซื้อครั้งถัดไป 12 พ.ย.     │
│ วันนี้     โทร — นัดเสนอราคารอบสอง        │ วิธีที่แนะนำ: เสนอของใหม่ก่อนใคร │
│ 2 ต.ค.    ซื้อ ฿48,000                    ├───────────────────────────────┤
│ 28 ก.ย.   ได้รับ LINE แคมเปญ "…"          │ ดีลที่เปิดอยู่                 │
│ 15 ก.ย.   นัดคุย — คุณแนน                 │ สั่งล็อตปีหน้า ฿220,000 · ต่อรอง │
└──────────────────────────────────────────┴───────────────────────────────┘
```

ไทม์ไลน์เดียวรวมทุกอย่าง — การซื้อ · ข้อความที่ส่ง · การคุย · งาน
แผงขวาคือเครื่องยนต์เดิมทั้งหมด ย้ายจากหน้าบรีฟมาอยู่ข้างคนที่มันพูดถึง

### หน้าแรก — เปิดมาแล้วรู้ว่าวันนี้ทำอะไร

| ส่วน | มาจาก |
|---|---|
| งานวันนี้ | `activities` ที่ถึงกำหนด |
| ดีลที่ค้าง | ดีลที่ไม่ขยับเกิน N วัน |
| ลูกค้าที่กำลังจะหาย | **สามใบของบรีฟเช้าเดิม** ย่อเป็นหนึ่งส่วน |
| ยอดในท่อ | มูลค่าดีลถ่วงด้วยโอกาสปิด |

### งบคลิก

| งาน | วันนี้ | เป้า |

| หาลูกค้าคนหนึ่ง | **ทำไม่ได้** | 2 — ⌘K พิมพ์ Enter |
| บันทึกการโทร | **ทำไม่ได้** | 2 — เปิดเรคคอร์ด พิมพ์ Enter |
| เพิ่มดีล | **ทำไม่ได้** | 3 |
| ย้ายดีลไปขั้นถัดไป | **ทำไม่ได้** | 1 — ลาก |

**หลัก** — แก้ข้อมูลในที่ (ไม่มีหน้าแก้ไขแยก) · ไม่มี modal ซ้อน modal · ค่าตั้งต้นกรอกให้ ·
ทุกอย่างกดจากคีย์บอร์ดได้

### ดีไซน์

- **หน้าตาแบบ Salesforce ≠ เอาแบรนด์ Salesforce มา** — ไม่ใช้สีฟ้า Lightning ไม่ใช้ภาพก้อนเมฆ
  ใช้เครื่องหมาย PARALLAX · สี signal `#0047ff` · IBM Plex Sans Thai ตามระบบแบรนด์เดิม
- **พื้นสว่างเป็นค่าตั้งต้น** — คอนโซลตอนนี้เป็นพื้นเข้ม ซึ่งเหมาะกับเดโมแต่ไม่เหมาะกับหน้าจอ
  ที่ทีมขายเปิดทั้งวัน (Salesforce · HubSpot · Zoho พื้นสว่างหมด) เก็บโหมดเข้มไว้เป็นตัวเลือก
- ตารางแน่น อ่านเร็ว — ข้อมูลคือพระเอก ไม่ใช่การ์ดใหญ่

ฟิลด์กำหนดเอง · ตัวสร้าง workflow · ซิงก์อีเมล/ปฏิทิน · แอปมือถือ · ใบเสนอราคา/ใบแจ้งหนี้ ·
แบ่งสิทธิ์ตามทีม/ภูมิภาค

## ความเสี่ยง

- **ไปแข่งตรงกับ Salesforce · HubSpot · Zoho** ซึ่งมีแผนฟรี — ต้องชนะด้วยสามอย่างที่เขาไม่มีพร้อมกัน:
  **ไทยทั้งระบบ · LINE เป็นช่องทางหลัก · วัดผลได้จริง** ขาดข้อใดข้อหนึ่งคือ HubSpot ที่แย่กว่า
- **เก็บ PII จริง = ภาระตาม PDPA** ที่ระบบตอนนี้หลีกเลี่ยงได้โดยการออกแบบ — ถอยกลับยาก
- **ข้อความทั้งเว็บต้องเขียนใหม่** — ทุกหน้าตอนนี้ขายเรื่อง "ต้นทุนต่อลูกค้าที่กลับมา" และ "สามงานต่อวัน"
