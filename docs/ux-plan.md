# PARALLAX · รีวิวเทียบ Salesforce และแผนทำ UX/UI ให้ง่ายขึ้น

ฉบับ 2026-10-16 · ร่างเพื่อให้เจ้าของตัดสิน · อ้างอิงหน้าจอจริงในเดโม Sunline (`npm run demo:seta`)
ข้อมูล Salesforce ในเอกสารนี้มาจากความรู้ทั่วไปเรื่อง Sales Cloud (Lightning Experience) ไม่ได้ตรวจราคาหรือรุ่นล่าสุด

---

## 1 · สรุปสั้น

- **ตัวระบบ (ข้อมูล · นโยบาย · PDPA) ของ PARALLAX ล้ำกว่า Salesforce แบบตั้งต้นในเรื่องที่ลูกค้าไทยเจ็บจริง** —
  รวมไฟล์เละเป็นคนเดียวพร้อมคิวตรวจ · คนย้ายบริษัทตามเวลา · ตัดสินว่า "ติดต่อได้ไหม" พร้อมเหตุผล · คำขอสิทธิ 30 วัน ·
  AI ที่อ้างหลักฐานทุกประโยค · ส่งออกแบบขออนุมัติ — Salesforce ต้องซื้อเพิ่มหรือจ้างที่ปรึกษาตั้งค่า
- **แต่หน้าจอยากกว่า Salesforce มาก** — เมนูใช้ศัพท์ภายใน (Data Vault · Account Workspace · ฐานการประมวลผล) ·
  หน้าแฟ้มบริษัทยาว 5,279 พิกเซล มีช่องกรอก 255 ช่องและปุ่ม 36 ปุ่มเปิดพร้อมกัน · ไม่มีค้นหารวม · ไม่มีหน้าดีล/ไปป์ไลน์ ·
  หน้าผู้ติดต่อยังเป็นของยุคค้าปลีก (ยอดซื้อ · ซื้อซ้ำ = 0 ทั้งหมดในบัญชี B2B)
- **ทางออก:** เอา "โครง" ของ Salesforce มาใช้ (แท็บตามชนิดข้อมูล · หน้ารายการ · หน้าระเบียนที่มีหัวสรุป + แท็บ + แก้ทีละช่อง ·
  ช่องบันทึกกิจกรรมด้านขวา · ไปป์ไลน์แบบลากวาง) แล้ว **ซ่อนความซับซ้อนด้านกำกับข้อมูลไว้หลังไอคอนตั้งค่า**
  ส่วนที่เป็นจุดขาย (ติดต่อได้ไหม · หลักฐาน · AI) เหลือเป็นป้ายเล็กและการ์ดในหน้าระเบียน
- **ขนาดงาน:** ~8–9 สัปดาห์ (คนเดียว) แบ่ง 7 ช่วง · ไม่แตะตรรกะเดิม — ชุดตรวจทั้งหมดต้องผ่านเหมือนเดิม

## 2 · เทียบทีละด้าน

| ด้าน | Salesforce (Sales Cloud) | PARALLAX ตอนนี้ | ใครดีกว่า |
|---|---|---|---|
| โครงข้อมูล | Lead · Account · Contact · Opportunity · Activity · Campaign — ชัด ทุกคนรู้จัก | บริษัท · คน (สองที่: "ผู้ติดต่อ" กับ "คนในบริษัท") · โอกาสขาย (ไม่มีหน้า) · แคมเปญ · งาน | **SF** ชัดกว่า |
| นำทาง | แท็บตามชนิดข้อมูลด้านบน · App Launcher | เมนูซ้าย 4 กลุ่ม 13 รายการ ศัพท์ภายใน | **SF** |
| ค้นหา | ค้นหารวมทุกชนิดข้อมูลที่แถบบน | ค้นแยกต่อหน้า (ชื่อบางส่วน · เบอร์/อีเมลต้องครบ) | **SF** |
| หน้ารายการ | คอลัมน์เรียงได้ · กรอง · มุมมองที่บันทึกไว้ · เลือกหลายรายการ | ตารางคงที่ · ตัวกรองแบบชิป · ไม่มีมุมมองบันทึก | **SF** |
| หน้าระเบียน | หัวสรุป (Highlights) 4–6 ช่อง · Path ขั้นตอน · แท็บ รายละเอียด/ที่เกี่ยวข้อง/กิจกรรม · แก้ทีละช่อง (ดินสอ) | หน้าเดียวยาว ทุกฟอร์มเปิดค้าง · ข้อความอธิบายทุกส่วน | **SF** |
| ไปป์ไลน์ดีล | Kanban ลากวาง · Path · พยากรณ์ | มีข้อมูลโอกาสขาย แต่ไม่มีหน้าของมัน | **SF** |
| กิจกรรม/งาน | ช่องบันทึกโทร/ประชุม/งานในหน้าระเบียน · ไทม์ไลน์ | ไทม์ไลน์ในแฟ้มบริษัท · จดโน้ตแล้วระบบแยก (S6) · หน้า "วันนี้" | เสมอ (PARALLAX จดโน้ตเร็วกว่า) |
| หน้าแรก | Home: งาน · ดีล · ข่าวสาร (ปรับแต่งได้) | "วันนี้": คิวเดียวเรียงตามความเร่ง พร้อมเหตุผล | **PARALLAX** |
| นำเข้า/ข้อมูลซ้ำ | Data Import Wizard · Duplicate Rules (จับซ้ำตามกฎ ไม่มีคิวรวมแบบย้อนได้) | ลงทะเบียนแหล่ง · ไฟล์เละ · ตรวจตัวตน · คิวตรวจ · รวมเป็นชุด · ย้อนได้ทั้งชุด | **PARALLAX** ชัดเจน |
| คนย้ายบริษัท | Contact ผูกกับ Account เดียว (ย้าย = แก้ทับ ประวัติหาย ถ้าไม่ตั้ง) | สังกัดตามเวลา · สัญญาณคนรู้จักย้ายบริษัท | **PARALLAX** |
| ความยินยอม/PDPA | Consent objects + ตั้งค่า/ซื้อเพิ่ม · ไม่ตัดสินให้ | บริการนโยบายตัดสิน ติดต่อได้/ต้องตรวจ/ห้าม พร้อมเหตุผล · DSAR 30 วัน · ทะเบียนการลบ · อายุข้อมูล | **PARALLAX** |
| AI | Einstein/Agentforce (ราคาเพิ่ม) | สรุปก่อนพบ · ร่างข้อความ · แยกโน้ต — ทุกประโยคอ้างหลักฐาน | **PARALLAX** (เชื่อถือได้กว่า) |
| รายงาน | Report builder + Dashboard เต็มรูป | ทบทวนรายสัปดาห์ · สรุปทางอีเมล · ไม่มีกราฟ | **SF** |
| สิทธิ์ | Profiles · Permission Sets · Sharing rules (ยืดหยุ่นแต่ยาก) | 6 บทบาทตายตัว · ระดับความลับ · MFA สำหรับงานเสี่ยง | เสมอ (PARALLAX ง่ายกว่า SF ยืดหยุ่นกว่า) |
| อีเมล/ปฏิทิน | ซิงก์ Gmail/Outlook | ไม่มี (คัดลอกร่างไปส่งเอง) | **SF** |
| มือถือ | แอป Salesforce | เว็บที่ย่อได้ ไม่มีแอป | **SF** |
| ตั้งระบบ | หลายสัปดาห์ · มักจ้างที่ปรึกษา | แม่แบบวัตถุประสงค์ · ตั้งต้นไม่เกิน 30 นาที (เป้า S9) | **PARALLAX** |
| ปรับแต่ง | Custom objects/fields · Flow · AppExchange | ไม่มี (ตั้งใจ) | SF — แต่ลูกค้าเป้าหมายไม่ต้องการ |

**อ่านตาราง:** PARALLAX ชนะเรื่อง "ข้อมูลถูกและใช้ได้ถูกกฎหมาย" · Salesforce ชนะเรื่อง "หน้าจอที่คนขายคุ้น" →
แผนนี้ปิดช่องฝั่งหน้าจอ ไม่ไล่ตามเรื่องที่ไม่ใช่ตลาดเรา (ปรับแต่ง · AppExchange · report builder)

## 3 · ปัญหาหน้าจอที่เจอ (จากเดโมจริง)

| # | ที่ไหน | อาการ | ผล |
|---|---|---|---|
| P1 | เมนูซ้าย | 4 กลุ่ม 13 รายการ · ศัพท์ภายใน: Data Vault · Account Workspace · Campaign Workspace · วัตถุประสงค์และฐาน · คิวตรวจตัวตน | คนขายไม่รู้ว่าจะไปไหน · งานกำกับข้อมูลปนกับงานขาย |

| P3 | ผู้ติดต่อ | ตัวเลขยุคค้าปลีก (ซื้อซ้ำ · ยอดซื้อ · มี LINE) ในบัญชี B2B ขึ้น 0 ทั้งหมด | ดูเหมือนระบบพัง |
| P4 | คนสองที่ | "ผู้ติดต่อ" (`/app/customers`) กับ "คนในบริษัท" (แฟ้มบริษัท) เป็นคนชุดเดียวกันแต่หน้าคนละแบบ | สับสน |
| P5 | โอกาสขาย | มีในข้อมูลแต่ไม่มีหน้า/ไปป์ไลน์ | ใช้เป็น CRM ขายไม่ครบ |
| P6 | ทุกหน้า | ย่อหน้าอธิบายยาวใต้หัวเรื่องทุกหน้าและทุกส่วน | อ่านเยอะ · หน้ายาว |

## 4 · โครงใหม่ (Information Architecture)

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ PARALLAX  [ค้นหาบริษัท คน ดีล…            ]   [+ ใหม่ ▾]   🔔  ⚙  (ฉัน)       │  ← แถบบน
├──────────────────────────────────────────────────────────────────────────────┤
│ หน้าแรก │ บริษัท │ ผู้ติดต่อ │ ดีล │ งาน │ แคมเปญ │ รายงาน                    │  ← แท็บตามชนิดข้อมูล
└──────────────────────────────────────────────────────────────────────────────┘
⚙ ตั้งค่า (ผู้ดูแล/ผู้ดูแลข้อมูลส่วนบุคคล/steward เห็นตามบทบาท):
   นำเข้าข้อมูล · ตรวจข้อมูลซ้ำ · นามบัตร · วัตถุประสงค์และอายุข้อมูล · คำขอสิทธิ · ส่งออก · ผู้ใช้และบทบาท · AI · ความปลอดภัย
```

| ใหม่ | มาจาก | หมายเหตุ |
|---|---|---|
| หน้าแรก | วันนี้ | + การ์ด "ดีลของฉัน" + "งานสัปดาห์นี้" |
| บริษัท | บัญชีบริษัท | |
| ผู้ติดต่อ | ผู้ติดต่อ + คนในบริษัท | **หน้าคนเดียว** สำหรับบัญชี B2B (ตัดตัวเลขค้าปลีก) |
| ดีล | (ใหม่) จาก `opportunities` | หน้ารายการ + Kanban |
| งาน | งานใน "วันนี้" + งานแคมเปญ | รายการงานทั้งหมด กรองของฉัน/ทีม |
| แคมเปญ | แคมเปญขาย | |
| รายงาน | ทบทวนรายสัปดาห์ | + 4 กราฟตายตัว |
| ⚙ ตั้งค่า | Data Vault · คิวตรวจตัวตน · คำขอสิทธิ · วัตถุประสงค์และฐาน · ส่งออก · ตั้งค่า · ผู้ดูแลระบบ | ใช้คำธรรมดา: "ตรวจข้อมูลซ้ำ" แทน "คิวตรวจตัวตน" · "นำเข้าข้อมูล" แทน "Data Vault" |

**ศัพท์:** ใช้ภาษาไทยธรรมดาที่คนขายพูด — บริษัท · ผู้ติดต่อ · ดีล · งาน · กิจกรรม · ติดต่อได้ / ต้องตรวจก่อน / ห้ามติดต่อ
ศัพท์กฎหมาย (ฐานการประมวลผล · ผู้ควบคุมข้อมูล) อยู่ในตั้งค่าเท่านั้น

## 5 · แม่แบบหน้าจอ 4 แบบ (ใช้ทั้งระบบ)

### 5.1 หน้ารายการ (List view) — บริษัท · ผู้ติดต่อ · ดีล · งาน · สมาชิกแคมเปญ
- หัว: ชื่อมุมมอง ▾ (ของฉัน · ทั้งหมด · ที่บันทึกไว้) · ปุ่ม **+ ใหม่** · ค้นในรายการ
- ตาราง: คอลัมน์เรียงได้ · ซ่อน/แสดงคอลัมน์ · ติ๊กหลายแถว → แถบงานกลุ่ม (มอบหมาย · เพิ่มเข้าแคมเปญ)
- ตัวกรองเป็นชิปด้านบน · จำมุมมองล่าสุดต่อผู้ใช้
- ผู้ติดต่อมีคอลัมน์ป้าย **ติดต่อได้ / ต้องตรวจ / ห้ามติดต่อ** (จากบริการนโยบายเดิม)

### 5.2 หน้าระเบียน (Record page) — บริษัท · ผู้ติดต่อ · ดีล
```
┌─────────────────────────────────────────────────────────────────┬───────────────────┐
│ 🏢 บริษัท สุวรรณพาวเวอร์ กรุ๊ป            [แก้ไข] [+ ดีล] [⋯]     │ บันทึกกิจกรรม       │
│ อุตสาหกรรม · เจ้าของบัญชี · คนปัจจุบัน 9 · ติดต่อล่าสุด 16 ต.ค.      │ [โทร][ประชุม][โน้ต]  │
├─────────────────────────────────────────────────────────────────┤ [งาน]              │
│ (ดีล) ● เปิด ─ ● เสนอราคา ─ ○ ต่อรอง ─ ○ ปิด      ← Path        │ ┌───────────────┐ │
├─────────────────────────────────────────────────────────────────┤ │ จดสั้น ๆ…       │ │
│ [ภาพรวม] [รายละเอียด] [คน] [ดีล] [กิจกรรม]                       │ └───────────────┘ │
│                                                                 │ ─ ไทม์ไลน์ ─       │
│ ภาพรวม: การ์ดสรุปก่อนพบ (AI · อ้างหลักฐาน) · คนสำคัญ 5 คน ·       │ 16 ต.ค. ประชุม…    │
│         ดีลที่เปิด · เส้นทางเข้าถึง                                 │ 14 ต.ค. โทร…       │
└─────────────────────────────────────────────────────────────────┴───────────────────┘
```
- หัวสรุป 4–6 ช่องเท่านั้น · รายละเอียดอยู่แท็บ "รายละเอียด" · **แก้ทีละช่องด้วยไอคอนดินสอ** (ไม่มีฟอร์มเปิดค้าง)
- ฟอร์มที่เหลือ (ความสัมพันธ์ · ระดับความลับ · ยืนยันสังกัด) อยู่ในเมนู ⋯ หรือเปิดเป็นหน้าต่าง
- ช่องบันทึกกิจกรรมด้านขวา = จดโน้ต S6 + ร่างข้อความ S7 + สร้างงาน · ไทม์ไลน์อยู่ใต้ช่อง
- หลักฐาน (แถวต้นทาง · ผู้ยืนยัน) ขึ้นเมื่อชี้ที่ค่า ไม่วางเป็นตาราง

### 5.3 ไปป์ไลน์ (Kanban) — ดีล
- คอลัมน์ตามขั้น · ลากการ์ดเปลี่ยนขั้น (บันทึก `record_versions` ตามเดิม) · ผลรวมมูลค่าต่อคอลัมน์ · กรองของฉัน/ทีม

### 5.4 หน้าต่างสร้างใหม่ (Modal) — บริษัท · ผู้ติดต่อ · ดีล · งาน
- ช่องบังคับไม่เกิน 5 ช่อง · ที่เหลือเติมทีหลังในหน้าระเบียน · ผู้ติดต่อใหม่ต้องเลือกแหล่ง/วัตถุประสงค์ (กติกาเดิม) จากรายการ ไม่ต้องพิมพ์

### 5.5 ระบบดีไซน์
- **ธีมสว่างเป็นค่าตั้งต้น** (ธีมมืดเป็นตัวเลือก) · ตัวอักษรเนื้อหา 14–15px · ระยะห่างตามตาราง 4/8px
- สีมีความหมายเดียว: น้ำเงิน = ทำ · เขียว = ติดต่อได้ · เหลือง = ต้องตรวจ · แดง = ห้าม/ลบ
- คอมโพเนนต์ชุดเดียว: Button · Badge · Tabs · DataTable · RecordHeader · Path · Modal · InlineField · ActivityComposer
