# PARALLAX · แผนทดสอบการใช้งานจริง (QA)

ฉบับ 2026-10-18 · ผู้ทดสอบ: Claude (บทบาท QA) · ผลการทดสอบอยู่ท้ายเอกสาร (บันทึกผล · บั๊ก)

## 1 · ขอบเขตและวิธีทดสอบ

- **ทดสอบแบบผู้ใช้จริง** ผ่านเบราว์เซอร์ทีละ flow: คลิก พิมพ์ และอ่านข้อความบนจอเหมือนคนขาย/หัวหน้าทีม ไม่เรียกฟังก์ชันตรง
- **สภาพแวดล้อม:** dev server บนเครื่อง (`npm run demo:seta` → ฐาน `.data/demo-seta.db`) บัญชี "Sunline Expo (สมมุติ)" ข้อมูลสมมุติทั้งหมด
  - production ไม่ใช้ทดสอบเชิงเขียน (มีข้อมูลจริง) · ทดสอบได้แค่ว่าหน้าเปิดได้หลังล็อกอิน
  - dev ไม่ล็อกอิน = ผู้ใช้ "owner" (เจ้าของบัญชี) — การทดสอบสิทธิ์รายบทบาทใช้ชุดตรวจอัตโนมัติ (verify:roles · verify:pg) + ตรวจข้อความปฏิเสธในโค้ด
- **ไม่อยู่ในขอบเขต:** อัปโหลดไฟล์บน production (ยังไม่มี ClamAV) · อีเมลสรุปรายสัปดาห์ (ต้องมี RESEND) · AI จริง (ไม่มีกุญแจบนเครื่อง — ทดสอบทางสำรองแทน)

### ระดับความรุนแรงของบั๊ก

| ระดับ | ความหมาย |
|---|---|
| **S1 วิกฤต** | ข้อมูลเสีย/หาย · ข้อมูลรั่วข้ามบัญชีหรือเกินสิทธิ์ · ทำงานหลักไม่ได้เลย |
| **S2 สูง** | flow หลักติดขัด ต้องอ้อม · ผลลัพธ์ผิด · ข้อความผิดจนทำให้ตัดสินใจผิด |
| **S3 กลาง** | ใช้งานได้แต่สับสน/ช้า/ต้องคลิกเกินจำเป็น · ขาด feedback |
| **S4 ต่ำ** | คำ การจัดวาง ความสวยงาม |

### เกณฑ์ผ่าน

แต่ละเคส: **ผ่าน** = ผลตรงที่คาดทุกข้อ · **ไม่ผ่าน** = เปิดบั๊กพร้อมขั้นตอนทำซ้ำ · **ข้าม** = ทำไม่ได้ในสภาพแวดล้อมนี้ (บอกเหตุผล)
ปล่อยรอบนี้ได้เมื่อ: ไม่มี S1/S2 ค้าง · S3 มีแผนแก้
