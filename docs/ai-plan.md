## 1 · หลักการ: AI อยู่ตรงไหน ไม่อยู่ตรงไหน

PARALLAX เป็นฐานข้อมูลที่ต้องเชื่อได้ — **AI เสนอ คนอนุมัติ เครื่องยนต์ที่ตรวจได้เป็นคนคำนวณ**

| AI ทำ | AI ไม่ทำ |
|---|---|
| อ่านสิ่งที่กฎอ่านไม่ออก (หัวคอลัมน์แปลก ตำแหน่งงานเขียนเอง ชื่อไทย↔อังกฤษ) | ตัดสินว่าใครเป็นคนเดียวกัน (เสนอได้ คนหรือกฎตัดสิน) |
| แปลงคำถามภาษาคนเป็นคำสั่ง Prism ที่ตรวจได้ | เขียน SQL หรือแตะฐานข้อมูลเอง |
| สรุปเรคคอร์ดและรายงานจากตัวเลขที่เครื่องยนต์คำนวณแล้ว | สร้างตัวเลข คำนวณ lift หรือ Relationship Equity |
| ร่างอีเมล กฎ Focus กฎตรวจ | ส่งอีเมล หรือใช้กฎจริงโดยไม่มีคนกด |
| อธิบายว่าทำไม (ผลต่างใน Rule Lab · คะแนน Focus) | เห็นเบอร์โทร/อีเมลจริงของใคร |

**ระบบต้องทำงานได้ครบโดยไม่มี AI** — ทุกความสามารถมีทางสำรองที่เป็นกฎ (ตอนนี้ `ai.ts` ทำแบบนี้อยู่แล้ว: ไม่มีคีย์ = ใช้สูตร)
AI ทำให้เร็วขึ้นและแม่นขึ้น ไม่ใช่สิ่งที่ระบบพึ่งพาเพื่อให้ถูกต้อง

## 2 · ทำไม Claude

| เหตุผล | ใช้ตรงไหน |
|---|---|
| **มีอยู่แล้วในโค้ด** — `lib/engine/ai.ts` ใช้ `@anthropic-ai/sdk` · structured outputs · แคชผลใน `ai_cache` · จัดการ refusal แล้ว | ต่อยอดได้ทันที ไม่ต้องเปลี่ยนผู้ให้บริการ |
| **Structured outputs** — บังคับผลเป็น JSON ตาม schema | ทุกผลที่เครื่องยนต์ใช้ต่อ (ป้าย · คำสั่ง Prism · ข้อเสนอรวม) |
| **Message Batches** — งานที่ไม่มีคนรอ ลดราคา 50% | จัดหมวดตำแหน่ง/องค์กร · ตรวจคู่ที่ไม่แน่ใจ ตอนนำเข้า |
| **Prompt caching** — ส่วนคำสั่งที่ซ้ำ (ชุดคำ · vocab ของลูกค้า) อ่านจากแคชราคาถูกมาก | ทุกงานของบัญชีเดียวกัน |
| **Citations** — คำตอบชี้กลับเอกสารที่ให้ไป | สรุปเรคคอร์ดที่ทุกประโยคชี้ Trace ได้ |
| **Web search (server tool)** — ค้นเว็บพร้อมแหล่งอ้างอิง | เติมข้อมูลองค์กร (เว็บไซต์ · อุตสาหกรรม) เมื่อลูกค้าเปิด |
| **บริบทยาว 1M โทเค็น** | อ่านตัวอย่างไฟล์ทั้งไฟล์เพื่อเดาว่าเป็นไฟล์อะไร |
| **ภาษาไทยดี** | ชื่อ ตำแหน่ง คำถาม รายงาน |

## 4 · ส่วนที่ต้องมี (สถาปัตยกรรม AI)

แนะนำ 12 ส่วน — ส่วนที่ 1–6 ต้องมีก่อนเปิด AI ให้ลูกค้ารายแรก

```
 ความสามารถ (A1…C2)
        │  callSteward(purpose, input)
        ▼
 ┌──────────────── AI Gateway  lib/engine/ai/ ────────────────┐
 │ ① Purpose registry   prompt · schema · effort · รุ่น · เวอร์ชัน │
 │ ② PII guard          ปิดบาง/ตัดค่าติดต่อก่อนส่ง · ตรวจซ้ำ     │
 │ ③ Policy             เปิด/ปิดต่อบัญชีต่อความสามารถ · งบรายเดือน │
 │ ④ Cache              ai_cache (hash input) + prompt caching    │
 │ ⑤ Call               messages.create / batches · fallbacks     │
 │ ⑥ Validate           schema ไม่ผ่าน = ทิ้ง · refusal = สำรอง    │
 │ ⑦ Ledger             ทุกคำขอ: บัญชี · ความสามารถ · โทเค็น · ฿   │
 └────────────────────────────────────────────────────────────┘
        ▼
 ผล + ป้าย "Claude เสนอ" → Calibrate / ร่าง / แผง Steward → คนอนุมัติ → change set (ย้อนกลับได้)
```

| # | ส่วน | ทำไมต้องมี |
|---|---|---|
| 1 | **AI Gateway จุดเดียว** (`lib/engine/ai/`) | ทุกคำขอผ่านที่เดียว — ตรวจ PII · งบ · บันทึก ได้ครบ · `boundaries.mts` ห้ามเรียก SDK นอก gateway |
| 2 | **PII guard** | ตัดเบอร์ อีเมลเต็ม LINE ที่อยู่ออกก่อนส่งทุกครั้ง (ส่งได้แค่โดเมนอีเมล ค่าที่ปิดบาง ชื่อ ตำแหน่ง องค์กร) · ตัวตรวจสแกน payload ซ้ำก่อนส่ง · `verify:steward` ทดสอบ |
| 3 | **Purpose registry** | แต่ละความสามารถมี prompt · schema · effort · รุ่น · เลขเวอร์ชัน เป็นไฟล์ในโค้ด — เปลี่ยน prompt = เปลี่ยนเวอร์ชัน = รัน eval |
| 4 | **Structured outputs ทุกผลที่เครื่องใช้ต่อ** | ผลไม่ตรง schema ถูกทิ้งและใช้ทางสำรอง · ไม่ใช้ forced `tool_choice` (Opus 5.5 ไม่รับ) |
| 5 | **Human-in-the-loop** | ผลของ AI ไปที่ Calibrate / ร่าง เท่านั้น · การกระทำจริงเป็น change set ที่ย้อนได้ · ป้าย "Claude เสนอ" ติดถาวรใน Trace |
| 6 | **AI Ledger + งบต่อบัญชี** | ทุกคำขอบันทึก (ความสามารถ · โมเดล · โทเค็น · ค่าใช้จ่าย · แคชโดนไหม) · งบรายเดือนพร้อมแจ้งเตือน 80% และหยุดที่ 100% (ทางสำรองยังทำงาน) · ลูกค้าเห็นได้ในหน้า Audit |
| 7 | **การตั้งค่าต่อบัญชี** | เปิด/ปิด AI ทั้งหมดหรือรายความสามารถ · ปิด web search ได้แยก · ค่าตั้งต้นสำหรับบัญชีใหม่ = ปิดจนกว่าลงนาม DPA ที่ระบุเรื่องนี้ |
| 8 | **Batches ผ่าน `work_queue`** | งานนำเข้าทั้งหมดส่งเป็น batch (ลด 50%) · ผลกลับมาไม่เรียงลำดับ — จับด้วย `custom_id` · รอผลผ่านคิว |
| 9 | **Prompt caching อย่างตั้งใจ** | ส่วนคงที่ (คำสั่ง + schema + ชุดคำของลูกค้า) อยู่หน้า · ส่วนเปลี่ยน (รายการตำแหน่ง/คำถาม) อยู่หลัง · ตรวจ `cache_read_input_tokens` ใน Ledger |
| 10 | **Refusal + fallback** | ตรวจ `stop_reason` ก่อนอ่านผลทุกครั้ง · เปิด server-side fallbacks (`fallbacks: "default"`) สำหรับ Opus 5.5 · ถ้ายังปฏิเสธ → ทางสำรองที่เป็นกฎ |
| 11 | **Evals** (หัวข้อ 7) | วัดทุกความสามารถด้วยชุดที่มีคำตอบ ก่อนเปลี่ยน prompt/รุ่น |
| 12 | **Feedback loop** | ทุกครั้งที่คนกดรับ/แก้/ปฏิเสธข้อเสนอ → บันทึก · อัตรารับต่ำ = ปิดความสามารถนั้นหรือแก้ prompt · ใช้ป้อน A8 (เสนอกฎจากการตัดสินใจ) |

### เปลี่ยนจากโค้ดตอนนี้

- `ai.ts` ใช้ `claude-opus-5` → ย้ายเป็น **`claude-opus-5-5`** (ถูกกว่า 20% · แคชถูกกว่า 60%)
  ตรวจแล้ว: เรียก SDK จุดเดียว · ใช้ structured outputs · effort `low` · ตรวจ refusal อยู่แล้ว · ไม่ใช้ forced `tool_choice` หรือปิด thinking
  → เปลี่ยนชื่อรุ่น + เพิ่ม fallbacks ได้เลย (Opus 5.5 ปิด thinking ไม่ได้ ใช้ effort คุมแทน · ค่าตั้งต้น effort คือ `medium` จึงต้องตั้งเองทุกความสามารถ)
- ย้าย `ai.ts` เข้าโครง gateway โดยรักษาพฤติกรรมเดิม (ไม่มีคีย์ = สูตร)

ทางเลือกที่ **เจ้าของตัดสิน** (AI-2): ใช้ Claude Haiku 5.5 (`claude-haiku-5-5`) กับงานจัดหมวดจำนวนมาก (A3 · A4 · B7) เพื่อลดต้นทุนอีก

## 6 · ข้อมูลส่วนบุคคล · PDPA · ที่ตั้งการประมวลผล

| เรื่อง | แผน |
|---|---|
| ส่งอะไรได้ | ชื่อ ตำแหน่ง ชื่อองค์กร โดเมนอีเมล ค่าที่ปิดบาง สถิติรวม · **ไม่ส่ง** เบอร์ อีเมลเต็ม LINE ที่อยู่ วันเกิด |
| ที่ตั้งการประมวลผล | Claude API เลือกที่ประมวลผลได้แค่ระดับ `us` หรือ `global` — **ไม่มีตัวเลือกในเอเชีย** → การส่งชื่อและตำแหน่งไปประมวลผลคือการโอนข้อมูลออกนอกประเทศตาม PDPA ต้องเขียนไว้ใน DPA และหน้า trust |
| ถ้าลูกค้าต้องการประมวลผลในภูมิภาค | ทางเลือกคือ Claude ผ่าน Amazon Bedrock หรือ Google Vertex AI ในภูมิภาคที่มีรุ่นที่ใช้ — ต้องตรวจว่ารุ่นไหนมีในภูมิภาคไหนก่อนสัญญา (gateway ทำให้เปลี่ยนผู้ให้บริการได้โดยไม่แก้ความสามารถ) |
| การเก็บข้อมูลฝั่ง Anthropic | ตรวจเงื่อนไขการเก็บข้อมูลของบัญชี API ก่อนรับลูกค้าจริง · ลูกค้าที่ต้องการ zero data retention ต้องทำข้อตกลงกับ Anthropic (รุ่น Fable ใช้กับ ZDR ไม่ได้ — เราไม่ใช้รุ่นนี้) |
| ความยินยอม | ไม่ต้องขอความยินยอมจากเจ้าของข้อมูลเพิ่มถ้าเป็นการประมวลผลในขอบเขตเดียวกับที่ลูกค้าเก็บมา แต่ **ให้นักกฎหมายยืนยัน** · ลูกค้าปิด AI ได้ทั้งหมด |
| บันทึก | Ledger เก็บว่าส่งอะไร (ชนิดฟิลด์ ไม่ใช่ค่า) เมื่อไร เพื่ออะไร — ตอบคำถามฝ่ายกฎหมายของลูกค้าได้ |
| แบรนด์ | ข้อความว่า "ใช้โมเดล Claude ของ Anthropic" บนหน้า trust ได้ · คำว่า "Powered by Claude" หรือโลโก้ ต้องตรวจแนวทางแบรนด์ของ Anthropic ก่อน |

## 7 · คุณภาพ: evals และการวัดว่า AI ช่วยจริง

| ความสามารถ | ชุดทดสอบ | เกณฑ์ |
|---|---|---|
| A3 ตำแหน่ง | 500 ตำแหน่งไทย/อังกฤษที่ติดป้ายด้วยมือ (รวมตัวย่อและสะกดผิด) | ระดับถูก ≥ 95% · สายงานถูก ≥ 90% |
| A4 องค์กร | 300 องค์กรสมมุติจากตัวสร้างข้อมูล (รู้คำตอบ) | อุตสาหกรรมถูก ≥ 90% |
| A5 คู่ไม่แน่ใจ | คู่จาก `truth.json` ที่กฎให้คะแนนกลาง ๆ | ต้องเพิ่ม recall โดย precision ไม่ลด — ถ้าไม่เพิ่ม ไม่เปิด |
| B1 Ask PARALLAX | 150 คำถามไทย/อังกฤษ พร้อมคำสั่ง Prism ที่ถูก | ตรงทุกส่วน ≥ 85% · ผิด schema = 0 |

| PII guard | payload ทุกความสามารถบนข้อมูลสมมุติ | ค่าติดต่อจริงหลุด = 0 |

- CI รันกับผลที่บันทึกไว้ (ไม่เรียก API จริง ไม่เสียเงิน) · eval กับ API จริงรันก่อนเปลี่ยน prompt/รุ่น และรายเดือน — **มีค่าใช้จ่าย เจ้าของอนุมัติงบก่อน**
- ในระบบจริงวัด **อัตรารับข้อเสนอ** ต่อความสามารถ (ส่วนที่ 12) — ต่ำกว่า 60% สองสัปดาห์ติด = ทบทวน

## 9 · สิ่งที่ตั้งใจไม่ให้ AI ทำ

- รวมคน แก้ค่า ลบ ส่งอีเมล หรือใช้กฎจริง โดยไม่มีคนกด
- เขียน SQL · เรียก API ภายในเอง · มีเครื่องมือที่เขียนข้อมูลได้
- สร้างหรือคำนวณตัวเลขที่แสดงเป็นข้อเท็จจริง (lift · Equity · จำนวนคน)

- เดาข้อมูลอ่อนไหวตามมาตรา 26 (ศาสนา สุขภาพ ความคิดเห็นทางการเมือง ฯลฯ) จากชื่อหรือข้อมูลอื่น
- เป็นแชตบอตทั่วไป — Steward ตอบเรื่องฐานข้อมูลของบัญชีนั้นเท่านั้น
